## Netlify deploy budget — deploy with judgment, not fear of running out

Netlify's free plan grants 300 credits per month, renewing every billing cycle — it is not a one-time lifetime pool. Each production deploy costs 15 credits, so roughly 20 deploys/month are included before any charge (checked directly on the account's Usage & billing page, Aug 2026). Editing `index.html` locally in the repo costs nothing. Committing and pushing to `main` triggers a live Netlify deploy and draws from that monthly allowance — reserve it for changes that actually matter to a purchase decision, since a dealer-facing page redeploying constantly for minor edits isn't the goal either, but don't hold back a genuinely useful update out of fear the credits won't come back — they do, every cycle. Editing the file and deciding whether to deploy it are two separate decisions with different bars.

## Steps

1. Read `index.html` for the current tracked listings, criteria, and links.
2. Re-check each tracked VIN's status using the Visor MCP connector first: `vins.get(vin, {include:["options"]})` returns current status (active/sold), price, mileage, dealer info (including phone), and build options in one call. Fall back to web search + fetching the dealer listing URL only for VINs Visor doesn't have (some dealers aren't in its feed — Driven Auto of Waukegan is a known example). A 404 from Visor or "no longer available"/404 on the dealer page is a strong sold signal — say so, don't assert certainty unless explicitly confirmed.
3. Search for new 2024 RS e-tron GT listings meeting all hard requirements from `CLAUDE.md` using Visor's `listings.search({make:"Audi", model:"RS e-tron GT", year:2024})` as the primary source — it returns VIN, price, mileage, dealer, a working `vdp_url`, and `photo_urls` in one call, which is far more reliable than scraping. Cross-check hard requirements (ventilation, roof) against the *options* array specifically: option code `9EF` ("Full Leather Interior") confers ventilation per `CLAUDE.md`; `3FG` ("Panoramic Fixed Glass Roof") confirms the roof. Treat an absent option code as inconclusive, not disconfirming — Visor's feed is sometimes incomplete for a given listing (seen on Select Auto Imports), so a missing `9EF` is a reason to flag for verification, not to hard-exclude, unless the dealer's own page also independently says "heated" only. Supplement with WebSearch across Cars.com, CarGurus, Edmunds, KBB, and individual dealer sites for coverage Visor lacks, prioritizing TX/nearby states per preference. **Known gap, confirmed Aug 13 2026:** Visor's `listings.search` can silently omit a VIN it otherwise knows about — brand-new listings especially (seen with a car listed same-day) sometimes don't appear in search results at all, or appear via direct `vins.get` lookup but with an empty `build`/`options` block, so the usual option-code checks never fire. Don't treat Visor's search result count as the full national list. At least once per run, pull Edmunds' full nationwide used-listing page for this model (`edmunds.com/used-audi-rs-e-tron-gt/`, paginate via `?pagenumber=N`) and diff its VINs against what's already tracked/excluded in `index.html` — this is what caught 3 missed listings in one pass (2 correctly hard-excludable on sight, 1 genuinely new and qualifying) that Visor's search alone didn't surface.
4. Flag anything ambiguous (interior color, ventilation, title, roof, structural/accident history) rather than silently excluding or silently clearing it — see `CLAUDE.md` for which flags are hard-exclude vs. needs-verification. A CARFAX snapshot badge on a dealer page (title brand, structural damage, etc.) is a summary signal, not confirmation either way — needs-verification until the actual report is read. For roof and ventilation specifically, check in this order: (1) Visor's build/options codes first — cheap, already being fetched, and sufficient on its own if it has an explicit code (e.g. `3FG` glass roof, `9EF` ventilation package). (2) If Visor's options data is missing or incomplete, check the first 5–10 photos in the dealer's gallery for a window sticker (usually easy to find, often photo #2) — its Packages/Options column gives a direct, explicit line rather than requiring inference. (3) Only fall back to "needs verification" if both of those come up empty. Don't skip straight to trusting the dealer's own written equipment text instead of checking the sticker — that text has already proven unreliable once (Select Auto Imports' text said "heated" while its actual sticker confirmed ventilated). See `CLAUDE.md` requirement #4 for exactly what to look for on the sticker.
5. For any new qualifying listing, use Visor's `vdp_url` as the direct listing link (it's typically the dealer's own working page) and one of its `photo_urls` as the thumbnail — download it into `images/` (`dealer-city.jpg`-style filename) per `CLAUDE.md`'s data-quality section. If Visor doesn't have the VIN, fall back to a web search for the VIN plus the dealer's domain, then try the VIN on Cars.com/CarGurus. If no direct page can be found after a reasonable attempt, link to the dealer's general used-inventory page instead and say so — never fabricate a URL. If no clean photo is found anywhere, skip the thumbnail rather than leave a broken image. Also add the dealer's phone number (from Visor's dealer data, or a quick web search if Visor doesn't have the dealer) as a tappable `tel:` link, and days-on-market if Visor provides it — see any existing card's `.meta-row` for the pattern.
6. If there's ANY change (new listing, price move, status change, link fix, a flag resolved, etc.), edit `index.html` directly to reflect it — keep the existing mobile-first card layout and structure, don't rebuild it from scratch each time. Keep cell/tag text terse per `CLAUDE.md`'s writing-style section. Notes use the collapsible one-line `<details class="card-note">` pattern (see any existing card) — don't revert to a plain always-expanded `<div>`, long notes will blow out the grid again. Each card needs a stable `data-id` (matching its image filename stem) and an edit (✎) + exclude (✕) button pair in `.dealer-link` — these back the manual link-correction and manual-exclude features in the live UI, so don't drop them when editing a card. Place each qualifying card in the correct section per `CLAUDE.md` requirement #1's interior-color tiers — black interior goes under **Perfect Fit**, Monaco Gray/Santos Brown under **Alternates** — and keep both sections' `(N)` counts and the header's overall "N tracked" total in sync.
7. Decide separately whether this change clears the bar for an actual deploy. Only commit and push to `main` if at least one of these is true:
   - A new listing was found meeting all hard requirements.
   - A tracked VIN's status changed in a way that affects viability (active → sold/delisted, a red flag confirmed or resolved, a previously-disqualifying issue cleared).
   - A price change of $1,000+ on a tracked, currently-viable VIN.
   Otherwise, leave the local edit uncommitted/unpushed — or if you're working in a persistent clone, commit locally for your own tracking but don't push. When in doubt, don't spend the deploy.
8. If you do push: pushing to `main` is the entire deploy process — Netlify's Git integration handles the rest automatically. No Netlify CLI or API call needed.
9. Report back concisely: what changed, whether it was published live and why (or why it wasn't, so nothing feels silently dropped), or a one-line "checked, no changes" if nothing moved.

## Guardrails

- Search/monitoring only — do not contact a dealer, submit a form, or take any purchase/payment action.
- If a VIN's data starts contradicting itself across sources (wrong model year, wildly different price/history), flag it explicitly as unreliable and recommend a phone call — treat this as a status change that clears the deploy bar.
- **Don't reinstate a VIN already sitting in the Excluded list as "sold/delisted" just because Visor, Edmunds, CarGurus, or Cars.com still shows it active.** Aggregator caches lag a dealer's real inventory by days to weeks — confirmed on the Auto Web Expo (Plano, TX) car, Aug 2026: Edmunds still listed it "active" at a stale price days after the dealer's own site had dropped the VIN from inventory entirely. Only move a sold-excluded VIN back to tracked if the dealer's own listing page directly confirms it's live again, or a phone call confirms it. This mirrors the existing "trust the dealer's own site over Visor for sold status" rule in `CLAUDE.md`, applied in reverse.
